# UX / UI 设计规则（已确认）

## 用户选择的视觉方向

用户选择了 A 方案：
- Fluent / 企业后台方向
- 浅色主界面
- 深蓝侧栏
- 蓝色主操作
- 绿色“正常”、橙色“警告”、红色“危险”
- 卡片式信息层级
- 大量清晰留白，但不能“全白没层次”

用户后来确认：

> 视觉定位 = **70% 专业 Web 管理后台 + 30% 桌面客户端质感**

不要做传统网站 Banner，也不要做成纯 Windows 客户端。

## 页面 Shell 必须统一
- 左侧深蓝固定导航
- 顶部主内容 Header
- 内容区浅灰背景
- 白色卡片
- 固定 spacing scale
- 同一圆角体系
- 同一阴影体系
- 同一图标体系
- 同一 Tabs 体系
- 同一按钮尺寸体系
- 同一表格体系

## 建议基础 token（可微调，但不可漂移）
- Page BG: `#F5F7FB` 附近
- Card: `#FFFFFF`
- Sidebar: `#071A33` / `#082445` 附近
- Primary: `#1677FF` / `#2563EB` 附近
- Main text: `#111827`
- Secondary text: `#64748B`
- Border: `#E5EAF2`
- Success: `#22C55E`
- Warning: `#F59E0B`
- Danger: `#EF4444`
- Purple accent only for少量辅助数据，不做主色

## 4 类固定页面模板

### Dashboard
用于：总览、性能

### 列表 + 详情
用于：玩家、联盟

### 表格 + 筛选
用于：舰船、MOD、日志、备份

### 左侧分类 + 设置区
用于：server.ini、系统设置

不要为每个页面发明新的布局语言。

## 高风险操作
必须与普通操作视觉分区：
- 强制终止
- Ban
- 扣资源
- 恢复备份
- 删除关键文件
- 修改高风险配置

必须二次确认。

## 图片生成/视觉确认规则
用户已经明确要求：
- 一个页面一张图
- 单独展示
- 禁止 4 合 1、2×2 拼图等合并展示
- 先自己 QA，再发用户

但对 Codex 更推荐：**真实写一个可运行的前端原型，然后浏览器截图**，不要依赖图片生成模型来输出中文界面，因为之前出现过中文模糊、布局漂移和凭空增加字段。

## 视觉 QA 检查表
每个页面截图前检查：
- 是否和 A 母版同一套导航？
- 导航宽度是否一致？
- 页面标题/Header 高度是否一致？
- 卡片圆角/阴影/边框是否一致？
- 中文是否清晰无乱码？
- 有没有添加未确认的游戏字段？
- Tabs 是否与信息架构一致？
- 危险操作是否单独分区？
- 页面在 1920×1080 是否合理？
- 1366×768 是否仍可用？
- 浏览器缩放/Windows 125% 下是否有截断？
