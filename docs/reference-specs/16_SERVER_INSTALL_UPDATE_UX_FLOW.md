# 服务器安装、导入与更新 UX 流程（已确认）

## 1. 决策结论

- SteamCMD 安装、Avorion 服务端安装、已有路径导入、路径检测与后续更新，统一放在“服务器管理 → 更新”。
- 不增加永久侧边栏入口，也不把首次配置做成另一套独立产品。
- `/server/update` 根据真实环境状态切换内容；必要时用 `/server/update/setup` 承载向导，但仍属于“更新”页。
- 已配置用户直接进入正常更新页；未配置、只配置一部分或检测异常时，才显示安装/导入流程。
- 本文既记录已确认 UX，也同步当前实现边界；浏览器流程、更新环境、两条安装 Operation、配置预检、安全配置应用，以及全新 Galaxy 的首次初始化/RCON 健康验证已实现；普通控制命令和防火墙继续按安全合同实施；自定义 Avorion MOD 明确不实施。

## 2. 页面状态模型

| 状态 | 含义 | 页面主要动作 |
| --- | --- | --- |
| `unconfigured` | SteamCMD 与服务端路径均未配置 | 全新安装、自动检测、选择已有路径 |
| `partial` | 只找到或只配置其中一项 | 补齐缺失项、重新检测、返回 |
| `detected` | 检测到候选路径，等待用户确认 | 确认使用、重新检测、手动选择 |
| `validating` | 正在验证路径、文件和版本 | 仅展示真实验证阶段，禁止重复提交 |
| `update-ready` | SteamCMD 与服务端可更新，但服务器管理配置尚未完成 | 进入服务器配置向导或进入正常更新页 |
| `configuring` | 服务器配置向导草稿阶段 | 上一步、下一步、保存草稿、取消 |
| `applying` | 正在执行安装、导入、配置或更新操作 | 查看阶段状态；仅在安全边界请求停止后续步骤 |
| `ready` | 安装/导入和配置均成功 | 进入控制页、查看更新状态 |
| `failed` | 某个原子步骤失败 | 查看错误、复制诊断信息、按明确动作重试或返回修改 |

建议接口字段：

```text
setupState = unconfigured | partial | detected | validating |
             update-ready | configuring | applying | ready | failed
```

## 3. 主流程

```text
进入“服务器管理 → 更新”
  → 读取真实配置与磁盘环境
  → 未配置 / 部分配置 / 已检测待确认 / 已配置
  → 用户确认路径
  → 验证 SteamCMD、服务端目录、可执行文件与版本
  → 更新环境可用？
      ├─ 否：返回缺失项和修复动作
      └─ 是：服务器管理配置完整？
          ├─ 是：进入正常更新页
          └─ 否：进入三步配置向导
              → 执行前复核
              → 服务端原子操作
              → 成功或失败恢复
```

路径确认只保存所选位置并触发验证，不更新、不移动、不覆盖任何文件。

## 5. 数据与安全规则

- 禁止假数据。未读取到的数据显示“未知”“未检测”或“不可用”，不得默认绿色正常。
- 不伪造进度百分比或预计剩余时间；只有后端提供可验证的字节数/步骤数时才展示定量进度。
- 执行状态由后端 Operation 提供，至少包含操作 ID、当前阶段、各阶段状态、开始/结束时间、错误码和可重试性。
- “停止”仅阻止后续原子步骤；当前不可中断步骤完成后再停，避免损坏安装目录。
- 进程失败后，端口、RCON、Galaxy 等依赖运行态的结果统一回到“未知/未验证”。
- 不做无限自动重试；重试必须由错误类型和幂等性决定，并让用户知晓。
- RCON 密码不得由查询接口返回，不得出现在日志、诊断包或操作摘要中。
- 防火墙变更必须单独说明影响并由用户明确确认；端口检测不等于授权改防火墙。
- 迁移路径前必须停止服务器、验证目标、评估空间、保留安全副本或回滚点；禁止边运行边移动。
- 浏览器刷新、关闭或断线不会取消服务端操作；重新进入页面后通过操作 ID 恢复状态。

## 6. 当前后端契约状态与缺口

当前已完成：

- SteamCMD 与 Avorion 服务端路径的独立保存、检测和真实验证。
- 只读服务器目录浏览，以及 SteamCMD / Avorion 服务端两个原子安装 Operation。
- 三步向导的非敏感草稿保存、RCON 密码不持久化，以及更新环境、Galaxy 路径、字段和端口占用的真实预检。
- `server.configure` Operation：应用前重新预检、确认服务端已停止、原子写入受控启动档案；已有 `server.ini` 时只更新已验证字段并回滚失败写入。
- `server.initialize` Operation：只对启用 RCON 的全新 Galaxy 开放；等待服务端生成 `server.ini`，真实发送 `/save` 与 `/stop`，停服后写入 RCON，重启并通过认证探针后才报告运行成功。

仍需补齐：

- `setupState` 与“更新环境可用 / 服务器管理配置完整”的分层状态。
- 导入写入、更新等 Operation 契约及阶段状态。
- 安全的停止后续步骤、显式重试、回滚/恢复动作与错误码。
- 已有 Galaxy 的启动/健康闭环和普通控制页生命周期命令的真实证据。

## 7. 路由与导航

- 永久入口：`/server/update`，侧边栏仍只有“服务器管理”。
- 配置向导使用 `/server/update?step=1..3`；旧的 `step=4` 链接兼容映射到新的第 3 步。浏览器前进/后退和刷新必须可恢复。
- 成功后可跳转 `/server/control`；失败页仍保留在当前 Operation 上，避免丢失诊断上下文。
- 不新增“安装中心”“路径管理”等未确认的侧边栏子页面。

## 8. 实施边界

2026-09-01 已按分阶段原则解锁两条独立命令：

- `steamcmd.install`：浏览器提交真实 Operation，在全新本地目标目录安装经过 Valve 签名验证的 SteamCMD 引导程序。
- `avorion.install`：只能在前一步成功后，使用已验证 SteamCMD 匿名安装 App 565060 的 public 分支；服务端先进入同父目录暂存位置，经成功标记和 Windows 服务端程序验证后原子落盘。

安装 Operation 都可通过 URL 恢复，失败时显示真实错误并保留可重试动作。安装成功仍不会启动服务端；导入写入、更新和控制命令继续等待各自的验证与失败恢复闭环。

配置向导现已收敛为三步并完成“草稿 + 真实预检”阶段：非敏感字段可恢复，Galaxy 目录通过 Server Agent 的真实目录选择器选择，执行前会检查更新环境、路径和本机端口占用。该阶段不写 `server.ini`，不启动服务端，不修改防火墙，也不安装或写入任何 MOD。

随后已完成 `server.configure` 安全应用阶段：预检通过后创建可恢复 Operation；新 Galaxy 只保存受控启动档案并明确延后首次初始化与 RCON，已有 Galaxy 才在停服且 INI 结构无歧义时原子更新已验证字段。页面必须逐项显示仍未执行的监听地址、独立 Query 端口与防火墙，不能把“配置应用成功”等同于“服务器已经可运行”。兼容字段 `installManagementMod` 始终强制为 `false`。

同日继续完成 `server.initialize`：新 Galaxy 配置成功后要求用户重新输入一次 RCON 密码，创建可恢复 Operation。Agent 首次启动精确服务端程序，等待 Avorion 自行创建 `server.ini`，依次执行 `/save`、`/stop` 并确认退出；然后停服写入 RCON、重新启动并通过真实 RCON 认证。页面只有取得进程、保存、停服、INI 与认证证据后才显示“服务器已启动并验证”。该命令没有扩大到控制页的通用启动、保存、停服或重启。

更新管理随后接入两个真实只读闭环：官方版本检查固定查询 App 565060 / public，并显示本机与官方 Build ID；服务器文件验证重新读取两个必需程序并返回大小、PE 文件头和 SHA-256 证据。两项 Operation ID 均保留在浏览器会话中，切换到其他服务器子页面后返回仍会恢复进度或最终结果；错误码和 SteamCMD 日志摘录直接显示。完整更新按钮继续禁用，不能把“版本已检查”或“文件校验通过”误报成备份、停服、更新、启动和回滚链已经可用。
