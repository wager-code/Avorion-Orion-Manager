# 产品目标与当前完成度

## 1. 软件要做什么

OrionAdmin 是面向 Avorion 专用服务器管理员的中文浏览器管理中心。目标不是做一个可以执行任意 RCON/Lua 的万能控制台，而是把高频管理动作做成可理解、可审计、可恢复的固定工作流。

当前产品形态：

- 一个本机 .NET Server Agent / Web API 进程。
- 一个 React + TypeScript 管理前端。
- 一个只安装在服务器端的专用 `OrionAdminBridge` MOD，用于官方服务器 API 才能完成的游戏内读取和受限写操作。
- 一个本机 SQLite 数据库，保存配置、操作、任务、历史和幂等状态。
- 单进程、单部署包、同一数据库；这是模块化单体，不是微服务。

主要用户是自己维护服务器的管理员。第一阶段以本机单管理员为主，后续才考虑 HTTPS、多用户权限、多节点和正式服务化。

## 2. 产品原则

1. 只显示可确认的真实数据；服务端停机、接口不通或能力未接入时明确显示不可用。
2. 游戏写操作必须有固定白名单、参数上限、管理员会话、CSRF、幂等键、持久审计、失败日志和结果复核。
3. 一个领域只设一个主要页面：玩家在线与玩家资产归玩家管理，联盟详情归联盟管理，舰船数据归舰船管理，批量奖励/活动/星区建设归游戏管理。
4. 其他页面只引用完成当前动作所需的最小上下文，不重复完整列表或状态卡。
5. 不用 Mock、猜测值或失效按钮把未完成功能伪装成可用。
6. 新功能先验证 Avorion 2.5.13 的官方依据，再写合同、后端、MOD、界面和真实验证。

## 5. 已支持的能力

### 5.1 服务器生命周期与维护

- SteamCMD 官方下载与签名检查、App 565060 public 安装、受管路径识别。
- 新 Galaxy 初始化、中文 INI 编码、RCON 延后配置与启动稳定观察。
- 受管启动、保存、安全关闭、安全重启、精确 PID 强制终止。
- Steam 官方 Build 查询、关键 PE 文件/大小/SHA-256 校验。
- 更新前安全点：停服后复制安装目录和 Galaxy，并逐文件哈希验证。
- 真实 CPU、进程内存、磁盘与主机网络采样及历史。
- 定时保存与定时安全重启的本地持久调度。
- 真实 `.bak` 扫描、备份恢复链路、日志读取和有限诊断。
- 读取真实已加载星区并安全卸载一个空闲星区；执行前再次拒绝有玩家或未加载的坐标，执行后复核。

### 5.2 玩家、联盟与奖励

- 管理组件握手、协议/版本/来源/请求编号和能力校验。
- 在线玩家、玩家索引、所在星区、加入/离开传播。
- 玩家 Credits 与铁、钛、纳奥石、崔钢、赛安金属、欧格石、阿沃里昂七种资源读取。
- 单个玩家增加 Credits 或一种矿物；有额度、确认、CSRF、幂等、Operation 和前后余额复核。
- 已知玩家最小身份，用于奖励目标选择，不复制在线、位置或资产。
- 最多 50 人批量奖励，支持游戏内邮件或直接到账；父批次与逐人 Operation 持久化，失败不自动重试。
- 从玩家所属关系发现联盟，读取领袖、主星区、成员、在线成员、舰船/空间站数。
- 联盟 Credits、七种资源、成员详情与单联盟增加资产。

### 5.3 Inventory 与物品目录

- 玩家/联盟 Inventory 读取：容量、槽位、数量、类型、名称、稀有度和安全图标路径。
- 炮塔核心参数：武器类型/分类、槽位类型、材质、平均/最高科技、DPS、伤害、射程、射速、精准度、槽位、尺寸、武器数、武装/工业、同轴、追踪、连续光束。
- 系统插件返回原版脚本和游戏实际 Seed。
- 11 个固定原版非剧情系统插件可以按普通至传奇稀有度单件发放，并复核 Inventory 精确增加 1。
- 共享目录登记 19 种普通炮塔和 39 个系统插件；分为 11 个已验证可发放、33 个仅目录、14 个剧情禁止。
- 本机运行时索引 922 个客户端图标；目录 58 个条目均能显示安全白名单图标。图标接口不接受任意磁盘路径。

## 6. 已实现但仍有限制

| 能力 | 当前限制 |
|---|---|
| 自动任务 | 长期运行和有玩家在线时的全面现场验收还不完整 |
| Steam Query | 游戏监听端口并连接 Steam，但标准 A2S 查询仍超时；在线人数用管理组件真实数据降级 |
| 完整服务器更新 | 版本检查、文件校验和更新前安全点已做；真正执行完整更新和从安全点恢复仍关闭 |
| 自动内存动作 | 告警策略和单个空星区卸载已做；自动批量卸载、临界自动重启关闭 |
| Inventory 发放 | 目前只开放 11 个系统插件；普通炮塔生成/预览/单件发放尚未完成 |
| 物品图片 | 能使用官方静态类型图标；程序化炮塔的真实三维库存缩略图没有已确认导出链路 |
| 公网部署 | 当前以本机单管理员为准；HTTPS、多用户、权限、多节点和正式 Windows 服务发布未完成 |

## 7. 尚未开发的主要产品模块

- 总览：跨模块健康摘要，但不能复制各页面的完整数据。
- 舰船管理：玩家/联盟舰船列表与详情、货舱、船员、系统、蓝图、创建新舰船。
- 游戏活动中心：海盗波次/BOSS、防守、索坦、护航、宝藏、打捞、采矿等。
- 星区建设：预检目标星区、模板预览、造船厂/装备船坞/资源站/修理船坞等安全部署。
- 活动记录：活动状态机、参与者、结果、奖励、失败和恢复。
- MOD 管理：读取现有第三方 MOD、配置、Workshop ID 线索和错误；不自动安装/更新/删除第三方 MOD。
- 文件与配置：受控文件浏览、INI/配置编辑、变更预览、备份和回滚。
- 设置：本机管理员、通知、路径和安全策略；多用户以后再规划。

## 8. 当前阶段判断

| 领域 | 阶段判断 |
|---|---|
| 服务器基础管理 | 已形成可运行主干，仍缺完整安全更新和发布级运维 |
| 玩家/联盟管理 | 真实读取与受限资产/Inventory 写入已经打通，仍缺更多授权动作 |
| 奖励中心 | 第一版真实批量链路完成 |
| 物品系统 | 目录与插件发放完成第一阶段；炮塔生成是下一关键里程碑 |
| 舰船管理 | 尚未进入正式 UI/完整后端开发 |
| 活动/星区建设 | 官方能力依据已整理，产品和安全状态机尚未实现 |
| 架构 | 后端和 MOD 边界健康；前端更新页需要先拆分 |

## 9. 当前明确不做

- 浏览器任意 Lua、任意 RCON、任意服务器控制台。
- 自动安装、启用、更新或删除第三方 Workshop MOD。
- 直接修改 Galaxy 数据库、玩家剧情进度或生成剧情/BOSS 专属物品。
- 用 Mock 替代正式数据，用无效按钮冒充功能。
- 自动批量删除星区实体、覆盖已有空间站或开放无上限生成。
- 随意传送、星区重置、未经验证的虫洞/银河门网络修改。
- 复制全套玩家在线/资产信息到奖励或活动页面。
- 承诺直接把现有舰船转让给另一玩家或联盟；官方 `ShipDatabaseEntry` 不支持修改现有舰船 Faction。
