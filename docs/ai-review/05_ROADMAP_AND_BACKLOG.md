# 功能规划与路线图

## 1. 路线图原则

- 先完成一个小而完整的垂直切片，再扩类型和批量。
- 游戏写功能必须在隔离 Galaxy 验证，不能只做按钮和接口。
- 未经验证的能力留在“待验证”，不进入正式按钮。
- 新功能进入唯一主页面；不会因为需要选玩家就再做一套玩家在线页。
- 先还清会阻碍扩展的结构债，再开发舰船、活动和星区建设等大模块。

## 2. 建议执行顺序

### M0：稳定模块化和页面基础

目标：为连续加功能建立不会继续膨胀的基线。

- 拆分 2403 行 `ServerUpdatePage.tsx`，保持同一路由和现有外观。
- 给未实现侧栏项/游戏标签添加明确“规划中”状态，或在可用前隐藏。
- 建立 `features/` 目录约定、前端 API 分区和页面行数检查。
- 保留并文档化全页截图脚本；增加运行态/停服态两套基线。
- 优化停服空态：最小原因 + 启动服务器/运行诊断，不保留大面积空表格。

完成标志：更新页拆分后流程测试和两档截图均无回归，架构脚本能阻止巨型页面再次出现。

### M1：普通炮塔生成预览与单件发放

目标：把 19 种普通炮塔从“目录”推进到可控生成，不一次开放全部复杂参数。

- 选择武器类型、材质、科技等级、稀有度和请求 Seed。
- 服务器生成只读预览：实际 Seed、槽位、DPS、伤害、射程、射速、精准度、武器数和特殊标记。
- 二次确认后每次只发放 1 件。
- 玩家和联盟沿用同一 Inventory 工作台，不创建新页面。
- 发放后复核库存精确增加 1，并读取实际生成参数。
- 首批逐种验证 19 种普通炮塔；某种未验证前保持目录/预览状态。

完成标志：至少一个最小白名单通过成功、拒绝、幂等、连接不确定、重启保存；再逐步扩大 19 种范围。

### M2：舰船管理第一版

目标：先做只读舰船详情，再做货舱和船员补充。

- 玩家/联盟舰船列表与归属、位置、状态。
- 舰船详情：计划、货物、船员、系统、炮塔设计的只读信息。
- 船员容量/职业预检；固定职业与数量白名单。
- 补最低船员、补理想船员、按职业补充。
- 货舱读取；设置/补充货物先做固定货物白名单和容量验证。
- 玩家/联盟详情只保留“查看关联舰船”入口和必要摘要。

完成标志：离线舰船、联盟舰船、容量不足、重复提交、重启保存均实测。

### M3：海盗活动第一版

目标：完成可创建、可追踪、可结束、可恢复的活动状态机。

- 选择空闲/允许活动的目标星区。
- 单波海盗生成：亡命徒、强盗、海盗、掠夺者等基础舰种。
- 难度由舰种、数量、波次、体积倍率和参与人数控制，不修改全服难度。
- 记录每个生成实体 ID、活动 ID、阶段和结果。
- 活动完成后通过现有奖励中心合同发奖。
- 支持服务端重启后的状态恢复或明确终止，不留下无法追踪的实体。

第二阶段再增加多波、航母、毁灭者、母舰/BOSS。

### M4：星区建设模板第一版

目标：让管理员快速部署一个可核对、可停止的服务型星区。

- 目标星区预检：玩家、已有实体、碰撞、最小间距、所有权、站点数量。
- 先提供四类模板：造船厂、装备船坞、资源中转/交易站、修理船坞。
- 执行前显示位置、归属、蓝图、材质和将创建的站点清单。
- 每个新实体保存 ID 和创建结果；部分失败可辨认。
- 默认不覆盖任何现有站点；不提供无上限批量生成。
- “删除/回滚模板”不能假设天然安全，必须先验证实体归属、依赖和玩家资产影响。

后续可扩：研究站、旅行枢纽、军事前哨、炮塔工厂、战斗机工厂、贸易站、走私市场、栖息地、生态站、赌场和核对过的自定义工厂。

### M5：更多活动玩法

在海盗活动状态机稳定后复用它：

- 星区/空间站防守。
- 索坦入侵。
- 商队护航或救援。
- 宝藏争夺和战利品空投。
- 废墟打捞。
- 采矿活动。
- 可认领小行星福利活动。

它们共享活动生命周期、实体登记、参与者、奖励、重启恢复和审计，不为每种活动重新造一套后台。

## 3. 已确认有开发基础，但尚未实现

### 玩家/联盟资产与通信

- 扣除 Credits 和矿物：需要余额预检、精确确认和复核。
- 玩家系统消息。
- 登录礼包、每日或节日奖励。
- 联盟成员职级、职级新增/删除和权限调整。

### Inventory 和物品

- 19 种普通炮塔生成、预览与发放。
- 经白名单验证的其他普通物品/可使用物品。
- 删除或调整受支持 Inventory 物品；这是高风险动作，优先级低于发放。
- 在星区为指定 Faction 掉落插件、炮塔、货物、资金或矿物。

### 舰船、船员、货舱和蓝图

- 玩家/联盟舰船列表与详情。
- 读取/设置数据库舰船船员，按职业补充、补最低/理想船员。
- 读取/设置舰船货物、机库、订单和蓝图。
- 从固定蓝图创建归玩家或联盟的新舰船。
- 在单舰安全验证后评估批量赠送新舰船。

### 星区和站点

- 空/资源小行星带、可认领大矿石。
- 残骸、容器和信标。
- 多站星区模板和经过核对的原版站点/工厂脚本。

## 4. 待验证，暂不承诺正式按钮

| 候选 | 为什么暂不承诺 |
|---|---|
| 程序化炮塔真实三维库存缩略图 | 官方已确认的是静态武器类型图标；未找到稳定批量导出具体炮塔渲染图的脚本接口 |
| 把系统插件直接安装到指定舰船插槽 | 发放到 Inventory 已验证，但远程安装、永久安装、移除和重启保存未验证 |
| 自定义舰长 | 构件存在，但属性、唯一性、容量和离线舰船行为未端到端验证 |
| Kick/Ban/Unban/管理员权限 | 可能走服务器命令/RCON，但目标版本精确命令、身份匹配和恢复未验证 |
| 活动范围排行榜 | 断线、联盟归属、防刷分、重复奖励和重启恢复规则未完成 |
| 星区占领战 | 需要独立状态机、冲突规则和多人验证 |
| 星际竞速 | 检查点、延迟和作弊规则未验证 |
| 临时虫洞远征 | 双向出口、重启、关闭和玩家滞留风险高 |
| 临时 PvP 竞技场 | 关系、友伤、复活和资产损失边界复杂 |
| 敌舰随机词条 | 平衡、兼容和清理没有白名单 |
| 完整产业链编排 | 单站可创建不等于跨站经济、货运和生产能可靠恢复 |
| 派系外交/战争控制 | 可能永久影响 Galaxy，需要可回滚模型 |

## 5. 当前明确不支持/不做

- 任意 Lua、任意 RCON、任意控制台。
- 自动管理第三方 Workshop MOD。
- 直接修改 Galaxy 数据库或剧情进度。
- 原版剧情 BOSS、剧情钥匙、剧情炮塔和特殊系统的普通发放入口。
- 把客户端全部图标打包再分发，直到许可边界确认。
- 自动删除/覆盖星区实体、无上限生成、随意传送或星区重置。
- 用“清 Lua GC”等技巧宣传为官方清内存。
- 玩家 IP 核心档案、全局击杀/死亡/成就页面。
- 直接更改现有舰船 Faction 以转让舰船。

## 6. 规划中的页面，不等于已完成

| 页面/入口 | 最小可用条件 |
|---|---|
| 总览 | 能提供跨模块异常、下一动作和近期 Operation 摘要，不复制各完整列表 |
| 舰船管理 | 至少有真实舰船列表和只读详情 |
| 活动中心 | 至少有一种活动的完整状态机和实服验证 |
| 星区建设 | 至少有一种站点模板的预检、预览、执行与复核 |
| 活动记录 | 活动已有持久 ID、阶段、结果和重启恢复 |
| MOD 管理 | 能真实读取已有 MOD/配置/错误，不自动修改第三方 MOD |
| 文件与配置 | 有受控路径、diff、备份、原子写入和回滚 |
| 设置 | 有真实可配置项和持久化，不是空表单 |

未满足最小条件时，入口应隐藏或明确显示“规划中”。

## 7. 每个里程碑的共同验收

1. 能力矩阵状态准确更新。
2. 模块边界检查、构建和自动测试通过。
3. 写操作具备白名单、上限、会话、CSRF、幂等、Operation、审计和结果复核。
4. 隔离 Galaxy 覆盖成功、拒绝、重复提交、连接不确定、重启保存。
5. 1440×900 与 1920×1080 覆盖空态、运行态、失败态、确认态和结果态。
6. 页面职责没有重复；另一个页面只引用最小上下文。
7. 文档、截图和真实证据进入仓库，下一位开发者无需依赖聊天记录。
