# 决策记录

## D-001：开发上下文随源码保存

日期：2026-09-14。
决定：使用 Git 托管代码与开发文档；每次可交接更新一起保存代码、任务状态和交接摘要。
影响：聊天不是项目进度的唯一来源；新 AI 从 README、PLAN、HANDOFF 恢复工作。

## D-002：使用用户指定的 GitHub 仓库

日期：2026-09-14。
决定：使用 `https://github.com/wager-code/Avorion-Orion-Manager`，主分支 `main`，仓库保持公开。
影响：代码、规划和交接一起提交；数据库、日志、恢复备份、Galaxy、密码和本机运行状态不提交。

## D-003：贡献使用工作分支和 Pull Request

日期：2026-09-15。
决定：仓库保持公开。外部贡献者可以查看、Fork 并提交 Pull Request；项目自己的 AI/Codex 开发也使用独立分支和 PR，`main` 作为稳定分支。
影响：后续功能、修复和仓库整理都从工作分支开始，合并前检查差异和验证结果。

## D-004：保留专用 OrionAdminBridge

日期：2026-09-07，2026-09-15 迁入当前决策表。
决定：继续使用项目自己的 `management-mod/OrionAdminBridge`，并按能力逐项验证开放；普通客户端不要求安装该组件。这个决定不扩大第三方 MOD 的能力范围。
影响：历史资料中与此冲突的旧结论只作为历史背景。新增游戏能力仍以真实接口验证、能力矩阵和安全边界为准。

## D-005：当前开发文档只保留一套主入口

日期：2026-09-15。
决定：当前开发状态由 `README.md`、`docs/development/PLAN.md`、`HANDOFF.md`、`WORKFLOW.md`、`DECISIONS.md` 以及根目录需求、能力矩阵、架构文件维护。旧 ZIP 交接说明、旧接续提示、迁移校验清单和一次性补丁不继续作为当前入口保留；需要追溯时使用 Git 历史。
影响：`docs/reference-specs/`、`docs/evidence/`、`docs/ai-review/` 可以继续保存历史资料，但不能自动覆盖当前源码事实。

## 历史产品约束的读取方式

既有中文 UI、模块化单体、真实数据和能力白名单等见根目录需求、能力矩阵及架构文件。历史资料用于追溯依据；未来新增写操作和部署范围仍按当前任务确认。
