# 基线实际验收

日期：2026-09-15。

本清单用于 M0-01～M0-05。自动 CI、页面实际运行和真实 Avorion 隔离服验收分开记录；任何一层通过都不能替代下一层。

## A. 自动启动冒烟

目标：证明当前提交不仅能编译，还能真正启动 API 与前端开发服务器，并通过前端代理访问健康接口和控制页。

CI 使用 Windows runner，在既有构建与测试完成后执行：

```powershell
./tools/run-local.ps1 -ApiPort 5188 -WebPort 4273 -SmokeTest
```

通过条件：

- API 进程成功启动。
- Vite 前端成功启动。
- `GET /api/v1/health` 经前端代理返回 `status=ok`。
- `/server/control` 返回 HTTP 200。
- SmokeTest 退出时只停止自己启动的 API / 前端进程。

## B. 本机页面验收

在真实开发电脑运行 `01-prepare.cmd`，然后 `02-start.cmd`。不启动 Avorion 游戏服务端时，先确认管理界面能正常打开且未知/未配置状态不会伪装为正常。

逐项检查：

| 项目 | 验收重点 | 状态 |
|---|---|---|
| 启动与导航 | API/前端启动、主要导航可进入、无白屏 | 待验收 |
| 更新页 | 未配置状态、路径选择、现有流程无回归 | 待验收 |
| 玩家管理 | 页面可打开；无游戏连接时状态准确 | 待验收 |
| 联盟管理 | 页面可打开；无游戏连接时状态准确 | 待验收 |
| Inventory | 玩家/联盟工作台布局、空态、不可用状态准确 | 待验收 |
| 备份 | 无有效 Galaxy 时不伪造备份数据 | 待验收 |
| 日志 | 无有效日志源时不伪造日志 | 待验收 |
| RCON | 未配置/未连接时显示真实状态 | 待验收 |

需要 UI 变化时先记录截图和问题，不在验收过程中顺手重设计页面。

## C. 隔离 Avorion 服务器验收

只使用已确认的测试服/隔离服，不对正式存档直接试验写操作。

验收前记录：Avorion 版本、目标 Galaxy、服务端运行状态、OrionAdminBridge MOD 版本与路径、RCON 端口/连接状态（不提交密码）。

逐项检查：

| 项目 | 验收重点 | 状态 |
|---|---|---|
| MOD Bridge hello | 协议版本、能力列表、组件版本可识别 | 待验收 |
| 在线玩家 | 真实在线玩家与位置读取 | 待验收 |
| 联盟 | 联盟列表/成员读取与真实游戏一致 | 待验收 |
| Inventory 读取 | 玩家/联盟库存读取与分页 | 待验收 |
| 已授权 System Upgrade 发放 | 仅在隔离服按现有限制验证，结果精确复核 | 待验收 |
| 备份/日志 | 指向实际测试 Galaxy 后读取真实文件 | 待验收 |
| 生命周期/RCON | 启停、保存、状态识别遵守现有安全边界 | 待验收 |

## 结果记录规则

- 自动 CI 结果记录 PR、commit 和 workflow run。
- 本机页面验收记录日期、commit、通过/失败项和必要截图。
- 游戏验收记录测试服范围和结果，但不提交密码、完整日志、数据库、Galaxy 或运行时秘密。
- 发现失败时先固定复现条件，再单独开修复分支；不要在验收分支同时加入新业务功能。
